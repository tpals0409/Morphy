Code signing policy

Status: preparing an application to SignPath Foundation. Morphy does not currently claim approval, a Foundation-issued certificate, or signed Windows releases.

Requested signing service

We intend to apply for free code signing provided by SignPath.io, with a certificate provided by SignPath Foundation. This is a planned arrangement, subject to approval, not an existing endorsement.

Project and responsibilities

Morphy-authored code is released under the MIT License. Third-party components retain their own licenses.

Source repository: tpals0409/Morphy.

Maintainer and proposed signing approver: tpals0409. Contributor changes are reviewed by the maintainer. Before production signing is enabled, the maintainer must configure the required multi-factor authentication and approval roles in GitHub and SignPath.

Signing will be limited to official Windows release artifacts built from this repository through GitHub Actions. Each signing request will require the designated approver's review under the approved SignPath policy. External libraries retain their upstream licenses and signatures; they are not represented as Morphy-authored code.

Privacy and network access

File conversion takes place locally. Morphy does not upload source documents or conversion results, and it does not send product analytics or conversion history.

Morphy contacts its release server to check for updates, including an automatic check when the app starts. Installing or updating the app downloads release files. Windows setup automatically downloads required document-conversion components from their official distribution servers when they are not already available; on macOS, those components are downloaded when the user enables document conversion.

These network requests expose normal connection information, such as the client's IP address and HTTP request headers, to the hosting providers. They do not include the contents of files selected for conversion. The project website is hosted on Cloudflare and also makes requests for release information.

The contact form on the website creates a public issue in the GitHub repository with the message, the chosen category and the visitor's operating system. An optional reply email is not included in the issue; it is stored privately in Cloudflare D1 and used only to reply to that message.

Local settings and diagnostic logs are stored on the device. A user may choose to share diagnostic information when reporting an issue.
