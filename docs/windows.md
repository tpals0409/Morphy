# Windows 개발 명세

2026-10-22 사용자 인터뷰에서 합의한 Windows 버전의 범위다. 이 문서는 구현 완료를 의미하지 않는다.

## 목표와 플랫폼

- macOS판과 기능이 같은 정식 Windows 버전을 목표로 한다.
- Windows 11 x64를 지원한다.
- 기존 Swift macOS 앱을 유지하고 Windows 앱은 C#/.NET으로 별도 구현한다.
- 관리자 권한 없이 현재 사용자 계정에 앱과 관리형 변환 엔진을 설치한다.
- 코드 서명 인증서나 서비스는 아직 없다. 개발을 먼저 진행하고 정식 배포 전에 준비한다.

## 사용 흐름

- 첫 실행에 사용 안내를 한 번 표시한다: 파일 선택 → Ctrl+Alt를 누른 채 원하는 형식으로 이동 → Ctrl+Alt 놓기.
- 파일 탐색기 또는 바탕화면에서 파일 하나를 선택했을 때만 도넛 메뉴를 연다.
- Windows 단축키는 Ctrl+Alt를 사용한다(사용자 후속 결정). 키를 누르면 선택 파일을 읽어 메뉴를 연다.
- 실제로 포인터를 원하는 섹터로 이동한 뒤 Ctrl+Alt를 놓으면 변환한다. 가운데 구멍이나 도넛 바깥에서 놓으면 취소한다. 누른 채 유지하는 동안 반복 입력으로 다시 열거나 닫지 않는다.
- 클릭 실행, Esc 취소, 앱 전환 취소, 바깥 클릭 취소와 클릭 전달 방지, 더 보기 동작은 macOS의 최신 결정(D6–D8)을 기준으로 한다.
- Ctrl/Alt의 누름·해제 이벤트를 모두 전달해 키가 눌린 상태로 남지 않도록 한다. 다른 키를 누르면 메뉴를 취소해 기존 조합을 전달한다. 다른 앱이나 Shift/Windows 키를 함께 누른 경우에는 열지 않으며, 이름 변경·주소 입력 등 텍스트 편집 중에는 메뉴를 열지 않는다.
- 여러 파일 선택과 지원하지 않는 파일에서는 메뉴를 표시하지 않는다.
- 로그인 시 자동 실행은 기본으로 끄고, 사용자가 설정에서 켰을 때만 활성화한다.

## 변환과 알림

- macOS판의 이미지, SVG, PDF, 텍스트, Word, Excel, PowerPoint 변환 경로를 기능 동등성의 기준으로 삼는다. Windows에서 필요한 코덱과 라이브러리는 조사·검증한다.
- 파일을 외부로 업로드하지 않고 로컬에서 변환한다.
- 원본을 변경하거나 결과를 덮어쓰지 않는다. 이름 충돌 시 번호를 붙이고, 결과를 검증한 뒤 저장한다.
- 원본 옆에 저장하되 쓰기 권한이 없으면 사용자가 다른 저장 폴더를 선택하도록 한다.
- 문서 변환 기능은 앱 설치 시 함께 다운로드하고 검증·설치한다(사용자 후속 결정). 설치 안내에 다운로드 크기와 필요한 공간을 표시하고, 준비가 끝난 뒤 앱을 실행한다. 엔진을 따로 삭제한 경우에는 다음 문서 변환 시 다시 추가한다.
- 성공·실패는 Windows 시스템 알림으로 안내한다.
- 트레이 메뉴에서 작업 상태와 실패 이유를 확인하고, 실패한 작업 재시도, 결과 열기, 탐색기에서 보기를 제공한다.

## 배포와 업데이트

- 기존 Cloudflare Worker와 R2에 Windows 설치 파일과 업데이트 정보를 추가한다(사용자 후속 결정). GitHub Actions는 빌드·검증·아티팩트 보관에 사용하며 Mac에서 내려받아 배포한다.
- 앱에서 새 버전을 안내하고, 사용자가 업데이트 버튼을 누르면 다운로드와 설치를 처리한다.
- 사용자 동작 없이 업데이트를 설치하지 않는다.
- 사용자별 설치를 유지하며 업데이트한다. 실행 파일 검증, 진행 중인 변환 보호, 설치 실패 시 복구는 업데이트 설계에 포함한다.
- 초기 공개 버전은 미서명 0.1.0 베타로 안내한다. 실제 Worker/R2 배포는 Mac에서 진행한다.

## 구현 순서와 검증

1. Windows 프로젝트와 트레이 앱, 최초 안내, 설정 저장을 구성한다.
2. 탐색기·바탕화면 선택 읽기와 Ctrl+Alt 입력을 연결하고 도넛 메뉴를 구현한다.
3. 안전한 출력 저장과 이미지·PDF 변환을 구현한 뒤 문서 변환 엔진을 연결한다.
4. 작업 대기열, 시스템 알림, 실패 재시도, 결과 열기를 연결한다.
5. 사용자별 설치와 Worker/R2 기반 업데이트를 구현한다.
6. macOS 변환 테스트 자료를 활용해 형식별 결과와 한국어 문서를 검증한다. 다중 모니터, 화면 배율, 화면 가장자리, Alt 조합, 이름 변경 중 입력도 확인한다.

기능 동등성은 위 단계 전체의 완료 기준이다. 단계별 구현을 정식 버전 완료로 취급하지 않는다.

## 구현 상태 (2026-10-22)

Windows 앱, 이미지·PDF·SVG·Office 변환, 설치 시 엔진 준비, 작업 취소와 재시도, 사용자별 설치·제거, Worker 업데이트 경로 및 CI를 구현했다. 현재 빌드·패키징·검증 방법과 제한은 `windows/README.md`에 기록한다.

로컬 패키지의 자체 검사와 설치 파일 무결성·파일 복구 검사를 통과했다. 실제 탐색기 입력, 혼합 DPI, 사용자 등록을 포함한 설치·제거, 공개 릴리스를 통한 업데이트와 macOS 결과의 시각적 비교는 별도 실기 검증이 필요하다. 코드 서명과 GitHub 릴리스 게시도 아직 수행하지 않았다.

최종 배포 앱으로 실행한 문서·PDF 통합 검사 36/36을 통과했다. 결과는 `build/windows-release-verification/report.json`, 설치 자체 검사 기록은 `build/windows-release/setup-selftest.txt`에 있다. 개발 빌드의 네이티브 DLL 누락을 게시 옵션 명시로 수정하고 자체 검사 및 트레이·입력 훅 시작/종료 검사도 통과했다. PDF TXT 검사는 원본 본문에 없는 단어 대신 실제 한국어 문구와 마지막 페이지 표식을 검증하도록 수정했다.

설치 시 `Cannot access a closed pipe` 오류는 공유 파이프의 reader가 먼저 닫힌 뒤 writer가 정리되며 발생했다. 두 객체에 `leaveOpen`을 적용해 파이프 소유자가 한 번만 닫도록 수정했다. 정상·작업 중 응답의 실제 named pipe 회귀 검사와 실제 앱 종료 요청을 통과한 설치 파일로 다시 패키징했다.
